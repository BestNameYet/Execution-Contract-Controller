# Simplified Transaction Layer Requirements

This table is the implementation checklist for the isolated simplified transaction layer under `minimal-controller-design/simplified-transaction-layer/`.

`MET` means the requirement is implemented by executable code in this subfolder and the exact script/line evidence is listed. `SPECIFIED` means the requirement is documented but no implementation script currently exists. `UNMET` means executable behavior is required and not yet implemented.

| ID | Requirement | Status | Scripts / lines where requirement is met |
|---|---|---|---|
| STL-001 | The simplified transaction layer must remain isolated from the existing `minimal_controller.py`; implementation in this folder must not modify the existing controller unless explicitly requested. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:3`. |
| STL-002 | The transaction layer must accept executable script source as its transaction input. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:7`. |
| STL-003 | For a transaction that contains a script, the transaction layer must generate/use a script runner and execute exactly the supplied script source. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:7,11`. |
| STL-004 | The execution derivative must use a single `subprocess.Popen(...)` child for the supplied script, rather than `subprocess.run(...)`, so the script may remain alive across multiple I/O exchanges. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:11`. |
| STL-005 | The transaction boundary must transparently carry caller/model input downward to the running script's stdin without interpreting its semantic content. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:7,9`. |
| STL-006 | The transaction boundary must transparently carry the running script's stdout upward to the caller/model without interpreting its semantic content. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:7,9`. |
| STL-007 | The transaction boundary must transparently carry the running script's stderr upward to the caller without interpreting its semantic content. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:7,9`. |
| STL-008 | A running script must be able to perform multiple stdin/stdout exchanges during one process lifetime before it exits. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:11`. |
| STL-009 | The transaction layer must remain semantically content-neutral: it must not interpret the meaning of stdin, stdout, stderr, or arbitrary script contents. | SPECIFIED | No implementation script yet. Specification only: `simplified-transaction-layer/README.md:9`. |
| STL-010 | The transaction layer must record every observable stdin use at the transaction boundary, preserving the ordered data transferred downward. | UNMET | None — no transaction implementation script exists in this subfolder. |
| STL-011 | The transaction layer must record every observable stdout use at the transaction boundary, preserving the ordered data transferred upward. | UNMET | None — no transaction implementation script exists in this subfolder. |
| STL-012 | The transaction layer must record every observable stderr use at the transaction boundary, preserving the ordered data transferred upward. | UNMET | None — no transaction implementation script exists in this subfolder. |
| STL-013 | The transaction receipt must record the executed script, process exit status, ordered stdin/stdout/stderr activity, derived transaction result, timestamps/lineage required by the transaction record, and persistence/integrity metadata. | UNMET | None — no receipt implementation script exists in this subfolder. README reserves receipt implementation for this folder at `simplified-transaction-layer/README.md:13`. |
| STL-014 | A transaction invocation with no script must execute no child script but must still generate and persist a transaction receipt describing the no-script transaction. | UNMET | None — no no-script transaction implementation exists in this subfolder. |
| STL-015 | At transaction completion, the transaction layer must determine whether the transaction return value is valid JSON and record that validity deterministically. | UNMET | None — JSON completion validation is not implemented. README reserves JSON behavior for this folder at `simplified-transaction-layer/README.md:13`. |
| STL-016 | Transaction-level JSON validation must be structural only: valid JSON vs. invalid JSON. It must not semantically validate arbitrary fields beyond the execution derivative's explicit continuation contract. | UNMET | None — JSON validation is not implemented. |
| STL-017 | If the completed transaction value is not valid JSON, the transaction must record `JSON-valid = false` and terminate progression by invoking the no-script transaction path; no new executable script is selected from that invalid value. | UNMET | None — invalid-JSON termination behavior is not implemented. |
| STL-018 | If a well-formed JSON object contains a `script` field under the execution derivative's continuation contract, the execution derivative must attempt to run the contents of that field as the next script. | UNMET | None — JSON continuation behavior is not implemented in this subfolder. README reserves JSON continuation behavior at `simplified-transaction-layer/README.md:13`. |
| STL-019 | The transaction layer must not infer whether arbitrary unlabeled text is executable by inspecting its contents; execution occurs only through the explicit script-oriented execution path/contract. | UNMET | None — no implementation script exists in this subfolder. |
| STL-020 | The execution runner must expose the running child's process lifecycle so the transaction can record process termination and final exit code after all stdin/stdout exchanges finish. | UNMET | None — no `Popen` runner implementation exists in this subfolder. |
| STL-021 | The implementation must preserve subprocess isolation: arbitrary script execution occurs in the spawned Python child rather than directly in the transaction process. | SPECIFIED | No implementation script yet. The intended `subprocess.Popen(...)` child is specified at `simplified-transaction-layer/README.md:11`. |
| STL-022 | Receipt generation and stream recording must not alter, consume for semantic purposes, or rewrite the data being passed between caller and executed script. | UNMET | None — transparent recording implementation does not yet exist. |
